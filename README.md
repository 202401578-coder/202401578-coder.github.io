# 이원경의 홈페이지

## 1. 목적

이 홈페이지는 연구를 함께할 분들과 채용 담당자분들께 제 연구를 소개하는 페이지입니다.
제가 관심 있는 연구 분야와 지금까지 연구한 것들을 보고 제 연구에 흥미를 가진 분과 함께 연구하거나, 입사 지원 때 제출할 포트폴리오로 쓰고 싶었습니다. 제가 이 분야에 얼마나 맞는 사람인지 보여 주는 것이 목표입니다.

### 페이지를 이렇게 구성한 이유

- **소개**: 비전공자로서 어떤 과정을 거쳐 이 일에 흥미를 갖게 되었고 무슨 일을 했는지 보여 주고 싶었습니다. 그래서 첫 화면에 어디 학생인지, 어느 연구실과 회사에서 무슨 일을 하는지, 어떤 언어와 자격을 갖췄는지를 한 번에 보이게 했습니다.
- **관심 분야**: 관심 분야마다 대표 프로젝트를 연결해, 누르면 그 프로젝트의 상세 창(목적·역할·결과)이 바로 열리게 했습니다. 예를 들어 Reasoning Verification은 추론형(CoT) 학습데이터 구축으로 연결됩니다.
- **이렇게 일합니다**: 제가 실제로 어떻게 일하고 무엇을 중요하게 생각하는지, 일하는 철학을 보여 주고 싶었습니다.
- **타임라인**: 처음에는 프로젝트를 나열만 했는데, "언제 무슨 일을 했고 지금은 뭘 하는지 보기 어렵다"는 피드백을 받아 월별 막대 그래프로 한눈에 보이게 만들었습니다. 막대를 누르면 해당 프로젝트로 이동합니다.
- **프로젝트**: 요약해서 볼 수 있는 카드 형식이 보기 좋다고 생각했고, 동시에 제가 진짜로 무슨 일을 했는지 증빙하고 싶었습니다. 그래서 카드를 누르면 목적·역할·결과와 예시 이미지·영상이 나오게 했습니다. 이미 진행한 연구의 보안을 생각해 중요한 부분은 블러(모자이크) 처리하거나 예시 데이터를 쓰는 등 신경 썼습니다.
- **경력·학력, 발표·수상**: 제 기본 정보를 한꺼번에 볼 수 있게 모았습니다.
- **블로그(AI 소식·연구일지)**: 이제부터 운영할 곳이라 아직 글이 적습니다. 글을 쓰면 자동으로 정리되어 올라가는 구조로 만들었습니다(아래 3번 참고).

페이지는 최대한 깔끔하고, 매끄럽게 내려가면서도 원하는 곳을 누르면 바로 볼 수 있게, 바로바로 반응하는 구조로 만들고 싶었습니다.

## 3. 실행·수정 방법

빌드 없이 바로 열리는 정적 사이트입니다. 외부 프레임워크는 쓰지 않았고 글꼴(Pretendard)만 CDN에서 불러옵니다.

| 파일 | 역할 |
|---|---|
| `index.html` | 메인 페이지 (소개·관심 분야·타임라인·프로젝트·경력 등) |
| `style.css` / `script.js` | 디자인과 동작 (다크 모드, 스크롤 효과, 프로젝트 필터·상세 창, 날짜에 따른 상태 자동 표시) |
| `theme-init.js` | 저장된 다크/라이트 설정을 화면이 그려지기 전에 적용 |
| `assets/` | 프로젝트 이미지·데모 영상, 블로그 그림(`assets/blog/`) |
| `blog/` | 블로그 페이지 |
| `data/posts.js` | 블로그 글 데이터 (자동 생성, 직접 고치지 않음) |
| `scripts/build-blog.mjs` | Google Docs 문서를 블로그 글로 바꾸는 스크립트 |
| `.github/workflows/blog-sync.yml` | 블로그를 자동으로 갱신하는 GitHub Actions |

**로컬 확인**: 저장소 폴더의 `index.html`을 브라우저로 엽니다.

**반영**: Stage → `git diff --cached` 확인 → Commit → Push → 공개 URL에서 확인

### 자주 고칠 부분 ① 프로젝트 추가

- 프로젝트 원본 자료는 제 컴퓨터의 작업목록 폴더(`사용할 자료/`)에 프로젝트별 폴더로 모읍니다. 이 폴더는 `.gitignore`에 넣어 공개 저장소에는 올라가지 않으므로, 다른 사람은 원본을 볼 수 없습니다.
- 새 프로젝트가 생기면 폴더를 하나 추가하고, 그 폴더만 Claude Code에 보여 줘서 `index.html`의 프로젝트 카드·상세 창·타임라인을 업데이트합니다. 공개해도 되는 이미지·영상만 골라 `assets/`에 넣습니다.
- 진행 중인 프로젝트는 상태 배지에 시작일·종료일(`data-start`, `data-end`)을 적어 두면, 방문한 날짜에 따라 예정 → 진행 중 → 완료로 자동으로 바뀝니다.

### 자주 고칠 부분 ② 블로그 글 쓰기 (Google Docs + GitHub Actions)

1. 웹에 게시해 둔 Google Docs 문서에 새 글을 씁니다. 글은 `10/04- 메모`처럼 **날짜 줄**로 시작합니다.
2. GitHub Actions(`Blog sync`)가 6시간마다 문서를 읽어서:
   - 날짜 줄을 기준으로 글을 나누고,
   - 글 안의 첫 제목으로 제목을 붙이고("연구계획서"처럼 종류만 적힌 제목이면 다음 제목인 실제 주제를 씀),
   - 본문 키워드로 **AI 소식 / 연구일지**를 자동 분류하고, 자주 나온 약어(SAM2, VLM 등)를 태그로 붙여서
   - `data/posts.js`로 저장해 자동으로 커밋합니다.
3. 분류를 직접 정하고 싶으면 날짜 줄에 `[AI소식]` 또는 `[연구일지]`를 넣습니다. 그 밖의 대괄호는 프로젝트 이름이 됩니다(예: `10/04- [연구일지][EarlyFailure] 메모`).
4. 바로 반영하고 싶으면 GitHub 저장소의 Actions 탭 → Blog sync → Run workflow를 누릅니다.

**원본 문서 보호**: 문서 주소는 사이트와 저장소 어디에도 적지 않고, GitHub Secret(`BLOG_DOC_URL`)에만 저장했습니다. 블로그에는 정리된 내용만 올라가고 원본 문서로 가는 링크는 없습니다. 다만 Google Docs의 "웹에 게시" 주소는 주소를 아는 사람은 열 수 있기 때문에, 문서에는 공개해도 되는 내용만 씁니다. 완전히 비공개로 하려면 게시를 끄고 Google Drive API로 읽는 방식으로 바꿀 예정입니다.

## 4. 현재 상태

### 완료

- 메인 페이지(다크/라이트 모드, 월별 타임라인, 프로젝트 상세 창, 데모 영상), 블로그와 자동 동기화, GitHub Pages 배포
- ETRI 과제 2건(2026.10 – 11)은 진행 중으로 표시했고, 구체적인 결과물은 과제 완료 후 보안사항을 지키는 범위에서 올릴 예정입니다.

### 만들면서 직접 확인하고 결정한 것

- **배치 순서**: 요약해서 볼 수 있는 내용은 위쪽에, 링크를 눌러 자세히 봐야 하는 내용은 아래쪽에 두었습니다. 연구를 먼저 보여 주고 싶어서 경력·학력·발표·수상은 뒤로 뺐습니다.
- **바로 연락**: 오른쪽 위에 Contact와 메일 주소를 잘 보이게 두어, 누르면 바로 메일을 보낼 수 있게 했습니다.
- **나이트 모드**: 밤에 작업하다 눈이 아파서 검정 배경의 다크 모드를 만들었습니다.
- **보안**: 영상의 지표 부분을 모자이크하고 중간 5초만 잘라 썼습니다. 개인정보가 담긴 원본(자기소개서, 참여확인서 등)은 저장소에서 제외했고, 이미지·영상의 메타데이터도 지웠습니다. 페이지에 콘텐츠 보안 정책(CSP)을 넣어 이 사이트와 글꼴 CDN 외의 스크립트는 실행되지 않게 했습니다.
- **휴대전화 확인**: 휴대전화에서 잘 보이는지 검토했습니다. PC(1280px)와 휴대전화(390px) 폭에서 가로 넘침이 없고, 모든 이미지에 대체텍스트가 있으며, 키보드 Tab 이동 시 초점 테두리가 보입니다.
- **블로그 방식 고민**: 원본 게시물(아직 공개하면 안 되는 것들)을 그대로 올릴 수는 없었습니다. 원래 Claude Code 아티팩트로 만든 페이지를 운영하고 있었지만 Actions에서 자동으로 읽게 하기 어려웠습니다. 수업에서 배운 Actions를 쓰고 싶어서, Google Docs를 웹에 게시하고 문서에는 올려도 되는 것만 쓰도록 한 뒤 날짜별·카테고리별로 나눠 블로그에 올리는 방식으로 만들었습니다.

### 남은 일

- 블로그 글의 이미지 첨부가 아직 안정적이지 않아 보완할 예정입니다.
- Google Docs 원본을 완전히 비공개로 바꾸는 방식(Drive API)으로 전환할 예정입니다.
- 새 프로젝트가 생기면 작업목록 폴더에 추가하고 홈페이지를 업데이트합니다.

### 사용한 자료와 AI 도움

- **사용한 자료**: 제 자기소개서, 학회 초록·포스터, 산학·사업 과제 자료(공개 가능한 이미지·영상만 사용), 과제 안내 PDF. 글꼴은 Pretendard(SIL Open Font License)입니다.
- **제가 결정한 것**
  - 홈페이지의 목적과 대상, 섹션 구성과 배치 순서
  - 각 섹션을 무엇으로 채울지와 세부 내용·사실관계
  - 디자인 방향: A/B 두 안 중 B안을 선택하고, 깔끔함·부드러운 스크롤·다크 모드를 정함
  - 공개해도 되는 자료와 가려야 할 부분: 영상 모자이크·발췌, ETRI 과제 세부 내용 비공개, 원본 자료 제외
  - 블로그 구조: Google Docs + Actions 자동화, AI 소식/연구일지 분류
  - 동료 의견 반영 여부
- **AI(Claude Code)에게 맡긴 것**
  - 제가 정한 구조와 내용을 바탕으로 한 HTML·CSS·JS 초안 작성
  - 영상 편집 작업(5초 발췌, 모자이크 처리)
  - 블로그 자동화 스크립트와 Actions 작성
  - 화면 캡처로 PC·휴대전화 레이아웃과 링크 점검
- 결과는 제가 브라우저에서 직접 확인하면서 수정 방향을 정했습니다.
